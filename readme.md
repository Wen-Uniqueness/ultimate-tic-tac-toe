# 超级井字棋（Ultimate Tic-Tac-Toe）开发文档 v1.6

## 1. 游戏概述
- **游戏名称**：超级井字棋（暂定）
- **游戏类型**：回合制抽象策略游戏
- **目标平台**：PC / 移动端 / Web
- **开发工具**：Godot 4.x（推荐 4.3 稳定版）
- **核心玩法**：在 3×3 宏观棋盘上，每个大格为一个 3×3 微观井字棋。通过占领微观棋盘来夺取宏观大格，最终在宏观棋盘上三连获胜。
- **项目结构**：
  `

## 2. 规则详述

### 2.1 棋盘与符号
- **宏观棋盘**：3×3 网格，坐标 (0,0) 左上至 (2,2) 右下。
- **微观棋盘**：每个宏观大格内包含 3×3 小格，独立进行井字棋。
- **默认符号**：A 为 **X**，B 为 **O**（后续版本支持自定义）。

### 2.2 回合流程
1. **先手**：A（X）先落子。
2. **落子限制**：
   - 一般情况下，玩家 **只能** 在 `next_macro` 指向的微观棋盘内落子。
   - 若 `next_macro` 为 `null`（即无限制），玩家可 **任意** 选择一个未被占领且未锁定的微观棋盘落子。
3. **执行落子**：在所选微观棋盘的一个空格内放置己方符号。
4. **微观判定**：
   - 若该微观棋盘 **出现三连**，则被当前玩家 **占领**。
   - 若该微观棋盘 **下满且无人三连**，则变为 **平局锁定**，不被视为任何一方占领。
5. **宏观判定**：
   - 占领或锁定后立刻检查宏观棋盘。
   - 若某方占领的大格在宏观棋盘形成横、竖或斜三连，游戏 **立即结束**，该方获胜。
   - 若所有微观棋盘均处于占领或者锁定状态，且无人胜利，则视为平局。
   - **平局锁定的大格不计入任何连线**，相当于双方障碍物。
6. **确定下回合限制**：
   - 用本回合落子的微观小格坐标 (r, c) 映射为宏观坐标，作为对手下一手的限制目标。
   - 若该目标微观棋盘 **已被占领或已锁定**，则 `next_macro` 设为 `null`，对手 **任意选择**。
7. **切换玩家**，重复第 2 步。

### 2.3 游戏结束条件
- **胜利**：一方在宏观棋盘达成三连。
- **平局**：
  - 所有宏观大格均被占领或锁定，无人三连。
  - 或轮到一方时，不存在任何合法落子点（所有可落子的微观棋盘均满，且当前无任意选择权或唯一目标已满）。

## 3. UI/UX 详细要求

### 3.1 可落子区域高亮
- 轮到玩家时，**强制高亮**所有合法落子区域：
  - 若 `next_macro` 不为空，仅高亮该目标微观棋盘内的空格；
  - 若 `next_macro` 为空，高亮所有 `IN_PLAY` 微观棋盘的全部空格。
- 高亮方式：空格打上淡绿色背景或边框发光，不可落子的格子灰显且无点击响应。

### 3.2 格子交互反馈（v1.3 新增）
- 每个格子（Cell）在鼠标交互时提供即时视觉反馈，包含两种状态：
  - **悬停高亮**：鼠标进入可下空格时，格子表面覆盖半透明白色叠加层（`alpha 0.25`），鼠标离开后恢复透明。
  - **点击变色**：鼠标按下时叠加层加深为灰色（`alpha 0.4`），松开后恢复悬停或透明状态。
- 实现方式：每个格子的根节点为 `Button`，附加 `cell.gd` 脚本，内部维护一个独立的 `ColorRect` 叠加层（`HoverOverlay`），通过 `mouse_entered`、`mouse_exited`、`button_down`、`button_up` 信号控制叠加层颜色。
- **设计要点**：
  - 叠加层独立于 `modulate`（由 `micro_board.gd` 控制 X/O 文字颜色），互不干扰。
  - 当格子被禁用（`disabled = true`）时，悬停和点击信号不产生任何效果。
  - 格子重置时叠加层自动恢复为透明。

### 3.3 自由选择权提示
- 当玩家获得任意选择权时（即对手被送去的微观棋盘不可用），需在 **状态栏或屏幕中央短暂显示提示**：
  > “对手选择的区域不可用，您现在可以任意选择落子区域。”
- 同时立刻将可落子区域切换为全局高亮（所有可用微棋盘空格）。

### 3.4 微观棋盘状态视觉
- 当微观棋盘发生 **三连** 或 **下满** 后，不再允许交互，视觉上：
  - **整体变淡**（半透明或灰蒙遮罩），以示不可用。
  - **中间显示巨大归属标记**：
	- 被 X 占领：显示一个半透明的巨大 **X**。
	- 被 O 占领：显示一个半透明的巨大 **O**。
	- 平局锁定：显示一个 **纯黑方块（或锁定图标）**，表示废格。
- 该效果在微观判定后立刻呈现，然后再检查宏观棋盘。

### 3.5 上一手落子标记
- 上一个被下子的微观小格内保留明显圆点标记，方便追踪。

### 3.6 宏观胜利特效
- 当一方宏观三连时，在宏观棋盘上 **绘制加粗高亮贯穿线**（颜色对应玩家）。

## 4. 数据模型与核心逻辑

### 4.1 枚举定义
```gdscript
enum CellState { EMPTY, X, O }

enum BoardState {
	IN_PLAY,      # 仍有空格，双方可下
	WON_BY_X,     # X 占领
	WON_BY_O,     # O 占领
	LOCKED        # 下满无人胜，永久不可用
}
```

### 4.2 微观棋盘（MicroBoard）
- 属性：`cells[3][3]` 为 `CellState`。
- 方法：
  - `place(row, col, player) -> bool`
  - `check_win() -> CellState` （返回 `EMPTY` 表示无人胜）
  - `is_full() -> bool`
  - `reset()`

### 4.3 游戏管理器（GameManager）
**核心变量：**
- `current_player: CellState`（X 或 O）
- `next_macro: Vector2i`（可为 `null`）
- `macro_boards: Array[MicroBoard]` 3×3
- `macro_states: Array[BoardState]` 3×3
- `move_history: Array[MoveRecord]`（用于悔棋与回放）

**MoveRecord 结构：**
```gdscript
{
	"player": CellState,
	"macro_pos": Vector2i,
	"cell_pos": Vector2i,
	"prev_macro_state": BoardState,  # 该微棋盘之前的状态
	"prev_next_macro": Variant,      # 上一回合的 next_macro（可为 null）
	"macro_win_flag": bool,          # 本次移动是否导致宏观胜利
	"winner": CellState              # 若胜利，记录胜者
}
```

**关键方法：**
- `get_valid_moves() -> Array`
- `make_move(macro_pos, cell_pos) -> GameResult`（返回 `{win: ..., draw: ...}`）
- `check_macro_win() -> CellState`
- `undo_last_move()`（回滚，需配合历史记录）

## 5. 悔棋功能（本地）

- **发起悔棋**：任何一方点击"悔棋"按钮，会向对方发送确认提示。
- **双方同意**：对方需在确认框中同意，悔棋才执行；若拒绝则继续对局。
- **连续悔棋**：可多次发起，但每一步都需要双方同意（不能单方面连续撤销）。
- **技术实现**：
  - 使用 `move_history` 完整保存每一步前的状态快照，包括 `macro_states`、各微棋盘内容、`next_macro`。
  - 悔棋时从历史中恢复上一步前的完整游戏状态，并弹出历史记录的最后一步。
- **联机扩展预留**：悔棋请求可封装成网络消息，由主机确认后广播状态回滚。

## 6. 计时系统（后期添加）

### 6.1 计时模式
- **参考围棋计时**：采用 **"基本时间 + 读秒/加时"**。
- 参数可调：
  - `main_time`：每位玩家的总基本时间（例如 10 分钟）。
  - `byo_yomi_periods`：基本时间耗尽后的读秒次数（例如 3 次）。
  - `byo_yomi_time`：每次读秒的步时限制（例如 30 秒）。
- 超时立即判负。

### 6.2 UI 表现
- 显示两位玩家的剩余基本时间及读秒状态。
- 轮到玩家时计时器走，落子后暂停当前玩家计时并启动对手计时。
- 最后一分钟/读秒阶段可加入声音提示。

### 6.3 与悔棋互动
- 悔棋后，时间应恢复到悔棋前的状态。历史记录中需保存时间戳或剩余时间，确保回滚时同步恢复计时器。

## 7. 联机对战（P2P，后期）

### 7.1 架构
- 使用 Godot 的 `ENetMultiplayerPeer` 实现 **P2P 直连**。
- 一方作为 **主机**（Host），拥有所有逻辑判定权；另一方为 **客户端**。
- 客户端仅发送"请求落子坐标"等输入，由主机权威判定并广播游戏状态。

### 7.2 关键流程
- **房间创建**：主机监听端口，客户端通过 IP/端口直连（或使用简单的匹配信令服务器）。
- **落子同步**：客户端发 `move_request` 至主机，主机验证合法性后执行，将新状态和 `next_macro` 等广播给所有客户端。
- **超时判负**：由主机计时，当某方超时，主机直接判负并通知双方。
- **悔棋同步**：发起方发送 `undo_request`，对方收到后弹出同意框；同意结果由主机收集并最终执行回滚，广播新状态。
- **断线处理**：若客户端断线，主机可选择等待重连或直接判负；若主机断线，则游戏中断（后期可考虑主机迁移）。

## 9. AI 对手架构（v1.4 新增）

### 9.1 设计目标
- 提供 **可调整难度**（简单 / 中等 / 困难），通过搜索深度和随机扰动控制
- 单步思考时间 ≤ 1 秒（PC），移动端 ≤ 2 秒
- 完整支持游戏所有规则（自由选择、锁定、平局等）
- 与 GameManager 解耦，通过标准接口交互

### 9.2 模块组成

| 模块 | 文件 | 职责 |
|------|------|------|
| AIPlayer | scripts/ai/ai_player.gd | AI 控制器，管理难度和时间预算 |
| GameState | scripts/ai/game_state.gd | 不可变状态快照，供搜索使用 |
| SearchEngine | scripts/ai/search_engine.gd | Alpha-Beta 剪枝 Minimax + 迭代加深 + 启发式排序 |
| AIEvaluation | scripts/ai/evaluation.gd | 评估函数，计算局面对当前玩家的优势分值 |
| EvalParams | scripts/ai/eval_params.gd | 评估参数对象，导出到 Inspector 方便调参 |
| AIGameManager | scripts/ai/ai_game_manager.gd | AI 模式专用 GameManager，集成完整游戏规则 + AI 调用 |

### 9.3 评估函数

`
score = micro_score × 0.7 + macro_score × 0.3
`

- **微观贡献**：二连威胁 +10/个，棋子 +1/个，阻挡对手二连 +5/个
- **宏观贡献**：二连机会 +20/个，阻挡对手二连 +15/个，占领大格 +5/个
- **动态调整**：临近终局时宏观权重提升至 0.9

（以上参数可通过 EvalParams 节点在 Godot Inspector 中实时调节）

### 9.4 搜索算法
- **核心**：带 Alpha-Beta 剪枝的 Minimax
- **启发式排序**：走法按评估值降序排序，提高剪枝效率
- **迭代加深**：从深度 2 开始，逐步加深到 4、6…，超时时返回当前最佳走法
- **提前终止**：发现一步致胜走法立即返回

### 9.5 难度配置

| 难度 | 最大深度 | 随机扰动 | 启发式排序 |
|------|---------|---------|-----------|
| 简单 | 2 | 20% | 关闭 |
| 中等 | 4 | 5% | 启用 |
| 困难 | 6（可至 8） | 0% | 启用 + 迭代加深 |

### 9.6 游戏内调节面板（v1.6 新增）

单人模式场景右侧面板增加了两个下拉菜单，方便玩家在游戏内直接调整 AI 行为和执子选择，无需进入 Inspector：

| 控件 | 选项 | 说明 |
|------|------|------|
| **AI 难度** | 简单 / 中等（默认） / 困难 | 控制搜索深度和随机扰动概率 |
| **玩家执子** | 先手（X，默认） / 后手（O） | 选择玩家使用的棋子，AI 自动使用另一侧 |

- 更改后**不会立即生效**，底部会出现黄色提示文字“更改后重启本局游戏后生效”
- 点击 **重新开始** 按钮后，新的难度和执子配置才会应用到下一局
- 底层将玩家选择的棋子记录在 `_player_side` 变量中，`current_player` 始终表示“当前该谁落子”（X 始终先手），两者语义分离，避免了混淆
